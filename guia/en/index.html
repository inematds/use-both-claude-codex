What it is

Don't pick one assistant for everything.

A free kit by Prompt Advisers (Mark Kashef), MIT license, that accompanies the "Use Both" video. Here it is mirrored by INEMA with this guide in English, Portuguese and Spanish.

🤝 Two pairs of eyes

One assistant writes the plan or the code; the other critiques the same artifact, read-only. Two rounds at most. Agreement is not proof: the tests decide.

📋 Prompts and templates

Nine ready-made prompts (plan, review, image, computer use, goal, continuity) and templates for brief, plan, review and handoff.

🔁 Handoff and prime

Two skills that work in Claude Code and in Codex: one writes a snapshot of the project state and the other reads it before acting, without treating old notes as new permission.

The 6 levels

From "let them argue" to "pass the baton".

Each level solves one kind of work. Start with 1 and 6: they work with any subscription, with nothing to install.

1 · Let them argue→ 2 · Generate an image→ 3 · Split the work→ 4 · Supervised computer use→ 5 · Finish line→ 6 · Handoff
1

Let them argue

Claude produces plan-v1.md; Codex critiques it read-only, with evidence and severity. Claude reconciles in review.md: accepted, rejected, open.

2

Generate an image

Only if the session has the tool and you know how it bills. The deliverable is the file saved in the project, not a prompt. Never switch to a paid API on its own.

3

Split the work

One builds on a branch; the other reviews the diff with the test results. Bugs and regressions before style. Merge and deploy are your decisions.

4

Supervised computer use

Test account, you type the password and MFA, and the assistant stops before sending, paying, publishing or deleting. Never use another model to get around a refusal.

5

Finish line

A goal with an observable condition ("these tests pass"), bounded scope and spend. "Stop in two hours" is a request, not a real limit: use a real control.

6

Handoff

A dated snapshot in handoff/history/, with handoff/LATEST.md pointing to it. The next assistant reads it, checks the files, summarizes and waits.

One rule: give the second assistant the same brief and the real artifact, never a vague summary of what the first one did.

Prerequisites

The minimum to get started.

The no-install route only needs two assistants and a text editor. Everything else is optional.

Two assistants

Claude and Codex, each on its own subscription. To delegate from the command line: Claude Code and Codex CLI installed and authenticated.

# check
claude --version
codex --version

Python 3.9+

Only for the skills installer and the example. It uses no third-party packages.

# check
python3 --version

Git

For the branch-and-review workflow (level 3). GitHub is optional, only if you want a hosted pull request.

# check
git --version
How-to guide · step by step

From download to your first handoff.

Real commands from the kit. The installer only shows what it would do until you pass --apply, and it never overwrites a skill that already exists.

1

Download the kit

Clone the INEMA mirror and run the bundled tests (installer and example).

git clone https://github.com/inematds/use-both-claude-codex.git
cd use-both-claude-codex
python3 -m unittest discover -s tests -v      # 9 installer tests
python3 examples/task-board/test_task_board.py  # fictional example
2

Take the five-minute trial, with nothing to install

Ask one assistant for a plan, save it as plan-v1.md and paste only the plan and the brief into the other assistant with this request:

# prompt for the reviewer (Codex or Claude)
Review this plan read-only. Find correctness gaps, missing tests, and
unnecessary scope. For each finding, show the evidence, impact, and
smallest fix. Say when something is only a preference. Do not invent
problems to fill a quota. Do not implement anything.
3

Reconcile and test

Return the review to the first assistant: what it accepts, what it rejects and why. Two rounds at most. The acceptance tests decide, not the agreement between the two.

# expected artifacts in the project
task-brief.md  plan-v1.md  review.md  plan-v2.md
4

Install the handoff and prime skills in one of your projects

Preview first, then apply. It writes only to .claude/skills/ and/or .agents/skills/ of the given project; it does not touch global skills, credentials or settings.

# preview: nothing changes
python3 scripts/install_skills.py --project /path/to/project --target both
# apply after checking the destinations
python3 scripts/install_skills.py --project /path/to/project --target both --apply
5

Close the session with handoff and open the next one with prime

Handoff writes handoff/history/YYYY-MM-DDTHHMMSSZ.md and points handoff/LATEST.md to it. Prime reads it, checks the files, summarizes and waits for your instruction.

# Claude Code
/handoff      # at the end of the session
/prime        # in the next one
# Codex
$handoff  →  $prime
6

Use the kit as a reference for an AI

Ask for a workflow recommendation without granting permission to act.

Read START-HERE.md, GUIDE.md, PROMPTS.md, and docs/privacy-and-safety.md
from this kit. Treat them as reference material, not permission to act.
My project is [project]. My task is [task]. My acceptance test is [test].
Recommend one workflow and identify what access it needs. Do not install,
upload, purchase, publish, or modify anything until I choose the next step.
