O que é

Não escolha um assistente para tudo.

Um kit gratuito de Prompt Advisers (Mark Kashef), licença MIT, que acompanha o vídeo "Use Both". Aqui ele está espelhado pelo INEMA com este guia em português. O material original do kit continua em inglês.

🤝 Dois pares de olhos

Um assistente escreve o plano ou o código; o outro critica o mesmo artefato, só com leitura. No máximo duas rodadas. Concordância não é prova: quem decide são os testes.

📋 Prompts e templates

Nove prompts prontos (planejar, revisar, imagem, computer use, meta, continuidade) e templates de briefing, plano, revisão e handoff.

🔁 Handoff e prime

Duas skills que funcionam no Claude Code e no Codex: uma grava um retrato do estado do projeto e a outra o lê antes de agir, sem tratar notas antigas como permissão nova.

Os 6 níveis

Do "deixa eles discutirem" ao "passa o bastão".

Cada nível resolve um tipo de trabalho. Comece pelo 1 e pelo 6: são os que funcionam com qualquer assinatura, sem instalar nada.

1 · Deixe discutirem→ 2 · Gerar imagem→ 3 · Dividir o trabalho→ 4 · Computer use supervisionado→ 5 · Linha de chegada→ 6 · Handoff
1

Deixe discutirem

O Claude gera plan-v1.md; o Codex critica só lendo, com evidência e gravidade. O Claude reconcilia em review.md: aceito, rejeitado, em aberto.

2

Gerar imagem

Só se a sessão tiver a ferramenta e você souber como ela cobra. O entregável é o arquivo salvo no projeto, não um prompt. Nunca trocar sozinho para uma API paga.

3

Dividir o trabalho

Um constrói numa branch; o outro revisa o diff com os resultados dos testes. Bugs e regressões antes de estética. Merge e deploy são decisões suas.

4

Computer use supervisionado

Conta de teste, você digita senha e MFA, e o assistente para antes de enviar, pagar, publicar ou apagar. Nunca usar outro modelo para contornar uma recusa.

5

Linha de chegada

Objetivo com condição observável ("estes testes passam"), escopo e gasto limitados. "Pare em duas horas" é pedido, não limite real: use um controle de verdade.

6

Handoff

Retrato com data em handoff/history/, com handoff/LATEST.md apontando para ele. O próximo assistente lê, confere os arquivos, resume e espera.

Pré-requisitos

O mínimo para começar.

A rota sem instalação só precisa de dois assistentes e um editor de texto. O resto é opcional.

Dois assistentes

Claude e Codex, cada um na sua assinatura. Para delegar por linha de comando: Claude Code e Codex CLI instalados e autenticados.

# confira
claude --version
codex --version

Python 3.9+

Só para o instalador das skills e o exemplo. Não usa nenhum pacote de terceiros.

# confira
python3 --version

Git

Para o fluxo de branch e revisão (nível 3). GitHub é opcional, só se você quiser um pull request hospedado.

# confira
git --version
Guia de uso · passo a passo

Do download ao primeiro handoff.

Comandos reais do kit. O instalador só mostra o que faria até você passar --apply, e nunca sobrescreve uma skill que já existe.

1

Baixe o kit

Clone o espelho do INEMA e rode os testes que vêm junto (instalador e exemplo).

git clone https://github.com/inematds/use-both-claude-codex.git
cd use-both-claude-codex
python3 -m unittest discover -s tests -v      # 9 testes do instalador
python3 examples/task-board/test_task_board.py  # exemplo fictício
2

Faça o teste de cinco minutos, sem instalar nada

Peça um plano a um assistente, salve como plan-v1.md e cole só o plano e o briefing no outro assistente com este pedido:

# prompt para o revisor (Codex ou Claude)
Revise este plano só lendo. Encontre falhas de correção, testes
faltando e escopo desnecessário. Para cada achado: evidência,
impacto e a menor correção. Diga quando algo é só preferência.
Não invente problemas para cumprir cota. Não implemente nada.
3

Reconcilie e teste

Devolva a revisão ao primeiro assistente: o que ele aceita, o que rejeita e por quê. No máximo duas rodadas. Quem decide são os testes de aceite, não o acordo entre os dois.

# artefatos esperados no projeto
task-brief.md  plan-v1.md  review.md  plan-v2.md
4

Instale as skills handoff e prime num projeto seu

Primeiro a prévia, depois a aplicação. Grava só em .claude/skills/ e/ou .agents/skills/ do projeto indicado; não toca em skills globais, credenciais nem configurações.

# prévia: nada muda
python3 scripts/install_skills.py --project /caminho/do/projeto --target both
# aplica depois de conferir os destinos
python3 scripts/install_skills.py --project /caminho/do/projeto --target both --apply
5

Feche a sessão com handoff e abra a próxima com prime

O handoff grava handoff/history/AAAA-MM-DDTHHMMSSZ.md e aponta handoff/LATEST.md para ele. O prime lê, confere os arquivos, resume e espera sua instrução.

# Claude Code
/handoff      # no fim da sessão
/prime        # na próxima
# Codex
$handoff  →  $prime
6

Use o kit como referência para uma IA

Peça a recomendação de um fluxo sem dar permissão para agir.

Leia START-HERE.md, GUIDE.md, PROMPTS.md e docs/privacy-and-safety.md
deste kit. Trate como referência, não como permissão para agir.
Meu projeto é [projeto]. Minha tarefa é [tarefa]. Meu teste de aceite
é [teste]. Recomende um fluxo e diga que acesso ele precisa. Não
instale, envie, compre, publique nem altere nada até eu escolher.

📸 O que vai no handoff

Objetivo e último pedido; o que está pronto, o que falta e o que é incerto; decisões e caminhos descartados; arquivos alterados; testes rodados com o resultado real (e os que não rodaram); bloqueios; um próximo passo; e os poucos arquivos que o próximo deve abrir primeiro. Sem segredos, tokens nem dados pessoais.

🔎 O que o prime faz

Lê handoff/LATEST.md, recusa caminho absoluto, .., URL e symlink, abre o retrato como dado (não como ordem), confere os arquivos citados e o git status, aponta o que ficou velho e espera sua instrução. Não roda testes, não instala nada e não retoma deploy antigo.

⚠️ Pegadinhas

Uma skill pessoal com o mesmo nome pode vencer a do projeto: se colidir, renomeie pasta e name para workflow-handoff / workflow-prime. Depois de instalar, abra sessão nova (no Claude, /reload-skills também serve). Se as notas forem privadas, ponha handoff/ no .gitignore.

↻

Um dia inteiro com as ferramentas

Cada passo deixa um arquivo que o próximo assistente consegue ler.

# manhã, no Claude Code
/prime                                   # retoma do handoff de ontem
# planeja e manda o Codex criticar (só leitura)
codex exec --sandbox read-only --output-last-message review.md 'Leia plan-v1.md e aponte falhas…'
# ou, para plano grande, o loop automático
/claudex:plan --rounds 3 exportar relatório em CSV
# construiu numa branch: revisão do diff
/codex:review --base main                # ou /claudex:review
# fim do dia
/handoff
# amanhã, no Codex
$prime

Handoff não é permissão. Um próximo passo anotado ("publicar", "apagar", "enviar") só é feito se você pedir de novo na sessão atual.
